# v2 audit: what the site already had before "The Interactive Kingdom"

Written at the start of v2 Phase 0 (November 2026, Working Edition 41), so v2 builds on what
exists instead of rebuilding it.

## Stack

- **Astro 7** static site, no framework islands (no React/Svelte/Vue). Every interactive piece is a
  small plain TypeScript `<script>` that Astro bundles and loads as a module.
- **Content** is generated by the Python importer (`importer/`, standard library only) from the
  manuscript `.docx` files into `src/content/` (Markdown) and `src/data/` (JSON). Never edited by hand.
- **Hosting:** GitHub Pages, deployed by GitHub Actions on every push (`npm ci && npm run build`, Node 24).
- **Search:** Pagefind, built after Astro (`astro build && pagefind --site dist`), loaded on demand.
- **Analytics:** GoatCounter script (no cookies) in `Base.astro`, production builds only.
  The account `knowledgekingdom` must still be created by Semir before counts are kept.
- **Windows:** Smart App Control blocks three unsigned native helpers (Astro compiler, oxc parser,
  Markdown renderer); `scripts/windows-wasm-fallback.mjs` installs their WebAssembly versions locally.

## Bulgarian version

- Pages under `/bg/` mirror the English ones. `npm run translate` (`importer/translate.py`) machine-translates
  new or changed sentences offline with OPUS-MT, caches every sentence in `content-meta/translations/`,
  and lets hand translations in `bg-overrides.json` win. It writes `src/content/bg/` and `src/data/bg/`.
- UI text lives in `src/i18n/ui.ts` (`t(lang, key)`), English and Bulgarian side by side.
- Bulgarian pages use Bulgarian-style Cyrillic letterforms (`lang="bg"` + font features).

## Timeline (v1)

- `importer/timeline.py` finds dated sentences in Parts II–III; `content-meta/timeline.json` holds
  hand corrections (exclusions, rewordings, added events, chapter spans) → `src/data/timeline.json`.
- `src/views/TimelineView.astro`: an overview strip (piecewise scale, log scale for deep time, one bar
  per chapter), an era-grouped event list, a chapter filter synced to `#ch-NNN`. HTML + CSS, ~2 KB of JS.
- v2 Phase 4 replaces the data source with the knowledge layer's `events.yaml` and adds zoom and lanes.

## Storage before v2

Separate `localStorage` keys, each read by its own code: `kk-read`, `kk-last`, `kk-fc-NNN` (one per
chapter), `kk-theme`, `kk-palette`. v2 Phase 0 moved all of them into `src/lib/reader-state.ts`
(keys `kk-state` and `kk-settings`); old keys are migrated once and removed.

## Things v2 Phase 0 fixed

- Section addresses cut mid-phrase (21 sections, e.g. `…-historical-claim-and-a/`): new rule never ends on a
  stop-word; old addresses redirect; readers' ticks follow the move.
- Chapter reading time now equals the opening plus the listed section times.
- The header overflowed at 360 px (theme and language buttons cut off) and buttons were 36 px on touch screens.
- Reported "raw frontmatter / hidden UI text visible": checked in a real browser at 360 px and 1280 px —
  not visible. The text-extraction tool was reading screen-reader-only labels ("Skip to content",
  "Open contents", "Chapter 001:"), which are correct and intended.
- 249 wrong Bulgarian flashcard texts (e.g. "Steelman" → "…City in Ontario Canada") replaced with
  hand translations while drafting Bulgarian for the knowledge layer.
